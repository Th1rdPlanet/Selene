# Selene Velocity adapter

Install the shaded Velocity JAR and edit `plugins/selene/velocity.properties`. This file contains only proxy responsibilities: backend, admission, routing, relay and proxy messages. Paper world/UI settings belong only on the authentication server.

`auth-server` and `default-server` are names from `velocity.toml`; Selene does not duplicate their addresses. Unauthenticated players can connect only to `auth-server`. After authentication Selene sends them to the last remembered gameplay server when enabled, otherwise `default-server`.

The relay requires a Paper client certificate trusted by the proxy and also pins the configured SHA-256 leaf certificate fingerprint. It accepts only `begin`, `answer`, `register`, `login`, and `close`, binds every request to the proxy's current player/IP/premium/session facts, and requires the player to be on the configured authentication server. Player plugin messages cannot grant authentication.

NORMAL and LOW do not rate-limit reconnects. MEDIUM rate-limits every IP and requires captcha. STRONG first requires an exact account/IP green pair, then premium players use a verified online-mode connection while offline accounts use their Selene password; captcha is disabled. `attack-auto` selects the bounded local rolling-window controller; all window, recovery, global thresholds and per-IP suspicion thresholds are configurable. Set it to false to use `attack-level` manually. A compatible fork may instead supply the nonblocking `ForkCapabilities` service; `fork-enabled=true` fails startup when that provider is absent. `medium-before-login` is present as a reserved configuration key but this build rejects `true`, because the fork handshake API and pre-join CAPTCHA transport are not implemented yet.

On stock Velocity, Selene first uses the backend snapshot and then asks Rust for the authoritative account type. Existing premium accounts use Velocity online mode; existing offline accounts always reach Selene password login even when the same name exists at Mojang. Only a new account triggers the bounded Mojang profile-name lookup when `premium-lookup-enabled=true`. A positive lookup only selects Velocity's online-mode handshake; successful ownership proof still comes from that cryptographic handshake. Lookup timeout, cache size/TTL and concurrency are configurable. An unavailable or saturated lookup fails closed for an unknown name, while a nonexistent profile continues through offline registration. Known premium accounts never fall back to offline mode after online verification fails.

All denial/player text lives under `message.*` in `velocity.properties`. Automatic mode uses connection rate, repeated IP activity and distinct usernames with configurable hysteresis. CPU/queue telemetry, GeoIP, ASN, Tor and VPN feeds are not implemented yet. Such data must never become the sole reason for denial.

The proxy periodically obtains bounded premium/green snapshots from Rust. If STRONG mode starts before a snapshot is available, the green set is empty and admission fails closed.
