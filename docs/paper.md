# Selene на Paper

Соберите `./gradlew :paper:build` и установите `paper/build/libs/paper-0.1.0-dev.jar`. Плагин собирается в bytecode Java 21 и рассчитан на Java 21–26. Целевой диапазон Paper — 1.21.1 и новее; нативные Dialog API изолированы в отдельном классе и используются только когда API присутствует.

`role: PROXY_AUTH` предназначен для отдельного auth-сервера. Такой Paper общается только с mTLS relay Velocity из `relay.properties`; адрес Rust backend на нём отсутствует. `role: NETWORK_NODE` предназначен для игровых серверов: он не запускает интерфейс авторизации, а публикует Velocity снимок ванильного whitelist и принимает сетевое maintenance-состояние. У каждого узла должен быть уникальный `node-id`. `role: STANDALONE` использует `standalone.properties` и подключается к backend напрямую. В каждом role-файле находятся только настройки этого узла. Значения `*-password-env` — имена переменных окружения, а не пароли.

В maintenance каждый Paper-узел пишет дополнительную диагностику смены состояния и whitelist без паролей, CAPTCHA-ответов, TOTP-кодов и recovery-кодов. Источником списка остаётся ванильный `whitelist.json`; итоговый допуск использует объединение списков всех подключённых узлов.

CAPTCHA и ввод учётных данных всегда проходят в limbo. `limbo.mode: MANAGED` создаёт пустой мир `selene_limbo`; `EXISTING` требует уже загруженный мир. `stage: BEFORE_JOIN` разрешён для `PROXY_AUTH`: игрок сначала входит только на auth Paper, проходит проверку и лишь после `AUTHENTICATED` впервые подключается к игровому backend. Это не означает проверку до протокольного Join Game — карта, чат и Dialog API доступны клиенту только в PLAY. Для standalone используется `AFTER_JOIN`. Во время проверки Selene блокирует координаты, yaw/pitch, телепорты не от плагинов, урон, атаки, взаимодействие, инвентарь, выбрасывание и подбор предметов, смену слота, публичный чат и посторонние команды. Игрока можно скрыть от остальных. После входа прежние location, scoreboard, XP и эффекты восстанавливаются, если другой плагин не успел заменить состояние, которым владела Selene.

Пятизначная CAPTCHA приходит из Rust backend как карта и как один из 64 глифов на каждую цифру. В `DIALOG_FONT` она показывается в нативном окне; `MAP` и автоматический fallback используют виртуальную карту. Ответ вводится обычным сообщением в чат, без команды, и отменяется до публикации.

`captcha-view: INTERACTIVE` включает второй тип CAPTCHA. Paper создаёт отдельный void-мир из `interactive-captcha.yml`, выделяет игроку удалённую приватную платформу и случайно выбирает одно простое действие: сломать целевой блок или дерево, взять/положить предмет в сундук, взаимодействовать со стойкой, кнопкой, рычагом или рамкой либо встать на отмеченный блок. Арена — небольшой парящий остров: каждый раз новый волнистый контур, конусное подбрюшье из земли и камня, трава, цветы и кусты по краю; по береговой линии стоит невидимый барьер в два блока. Кнопка, рычаг и рамка висят на боковой стороне каменного столбика, повёрнутой к игроку; рамка закреплена (`fixed`), не сохраняется в мире и не может отвалиться или сломаться, а забрать из неё изумруд можно и правым, и левым кликом. Клики по траве, цветам и листве не считаются ошибкой; для руды и дерева выдаются каменная кирка и топор. Верхний слой (`SOLID`, `RANDOM`, `CHECKERBOARD` из `floor-materials`), материалы подбрюшья и растений, плотность растений, размеры, расстояние арен, число приманок, предел ошибок, веса сценариев, целевые блоки и предметы настраиваются в этом Paper-файле.

Игроки на интерактивных аренах скрыты друг от друга вместе с TAB/name tag, их инвентарь временно заменяется безопасным набором задания, чат и команды блокируются, а урон, голод, размещение и выход за границу отменяются. После заданного числа ошибок арена пересобирается. При успехе, отключении или остановке плагина сущности и блоки удаляются, слот арены освобождается, а исходный инвентарь восстанавливается. Rust backend остаётся источником истины: Paper не может завершить CAPTCHA без текущего одноразового nonce.

Для входа используются `/login` и `/register` без аргументов. На Paper с Dialog API открывается форма с одним полем входа или двумя полями регистрации. Если аккаунт защищён TOTP, после пароля появляется отдельное поле для шести цифр или recovery-кода. Chat fallback также перехватывает эти значения и не публикует их. Аргументы с паролями и кодами не используются.

Команда `/2fa` обрабатывается Velocity. Auth Paper получает только connection-bound management action. Enable показывает QR через `selene:qr`, ручной Base32 ключ и поле подтверждения. Если QR-шрифт недоступен, ручной ключ остаётся доступен. После подтверждения recovery-коды показываются один раз; возврат на предыдущий сервер происходит только после кнопки «Я сохранил коды». В `dialogs.totp`, `totp-setup`, `recovery` и `management-result` настраиваются ширины, labels, кнопки и их размещение. Resource pack устанавливается через ItemsAdder/Oraxen по инструкции `integrations/itemsadder/README.md`.

Все сообщения, labels диалогов, title, subtitle, actionbar и scoreboard поддерживают MiniMessage. В `presentation` каждый канал включается независимо и имеет отдельный формат для `connecting`, `captcha`, `login`, `register` и `processing`. `actionbar` — это строка над хотбаром. `<seconds>` показывает остаток времени; scoreboard принимает 1–15 строк. Полоса опыта и число уровня включаются отдельно. Selene не содержит resource pack: `resource-pack-provider` лишь проверяет наличие Oraxen или ItemsAdder, а `<font:...>` и глифы указываются прямо в шаблонах MiniMessage.

`packet-events-mode: AUTO` включает PacketEvents только в `STANDALONE`, где до входа нужно скрывать настоящий игровой инвентарь. На выделенном `PROXY_AUTH` сервере инвентарь изолирован и PacketEvents не требуется. `ENABLED` и `DISABLED` принудительно меняют это поведение. При активации Selene проверяет, что API PacketEvents уже loaded/initialized, регистрирует firewall-listener, печатает фактическую версию и снимает listener при выключении.

Standalone Paper поддерживает `selene account list [page]`, `info <name>`, `delete <name>`, `reset-password <name>` и `reset-totp <name>`. Консоли доступны все операции; вошедшему игроку нужны права `selene.command.account.view` или `selene.command.account.manage`. На `PROXY_AUTH` управление аккаунтами выполняется через Velocity. Команда `selene reload` с правом `selene.command.reload` сначала проверяет конфигурацию, затем безопасно перезапускает плагин и отключает игроков с auth-сервера, чтобы ни одна старая сессия не пережила reload.

Старый блок `auth-location` удалён. Замените его на `limbo.*`; при обнаружении legacy-ключа Selene выводит точный путь и останавливает запуск. Плагин также останавливает сервер при отсутствующем limbo-мире, неверных bounds, сломанном MiniMessage, TLS-файле или переменной окружения. Hot reload не поддерживается.
