# Selene Paper adapter

Build `./gradlew :paper:build`; install the unclassified JAR from `paper/build/libs` and PacketEvents **2.9.5**. Compiles against Paper 1.21.8, Java 21 bytecode. Runtime Java 21–26 is intended; only the locally available JVM has been tested. Versions beginning 1.21.1 are intended compatibility targets, not an executed server/client matrix.

On first startup configure `plugins/Selene/config.yml`. `PROXY_AUTH` creates/reads **only relay.properties**, containing the Velocity relay endpoint, this Paper node's PKCS12 identity, and proxy trust store. It never creates or reads standalone backend settings. `STANDALONE` creates/reads **only standalone.properties**, with the backend endpoint. Passwords for PKCS12 files come from the named environment variables. Failure to initialize stops the server. PacketEvents is a soft dependency so Selene can actually execute its fail-closed shutdown when PacketEvents is missing, rather than simply being disabled by Bukkit.

Standalone premium proof is exclusively `Bukkit.getOnlineMode()`. An offline-mode Paper cannot claim premium identity from UUIDs. Proxied deployments must use Velocity modern secure forwarding and prevent direct player access to the auth server; the relay owns authoritative player identity, IP, session, and premium status. Selene is an auth-server adapter, not a plugin to install on every destination server.

Commands: `/captcha <digits>`, `/login <password>`, `/register <password> <password>`. Backend replies control progression. Every connection is locked before its first inventory packet; unknown PacketEvents User objects default to denied. The firewall suppresses window contents, slot changes, cursor items, player inventory updates, entity equipment and entity metadata until that exact User authenticates. The inbound allowlist blocks item usage, inventory mutation/query, plugin channels and world interaction before Bukkit handlers; event guards also prevent movement, damage, public chat and unrelated commands. Reconnects use distinct object identity and cannot inherit permission. Async callbacks check the exact session object before applying results. Disable/reload kicks existing players; hot reload is unsupported.

Captcha PNGs arrive from Rust, render into a private map and are sent as a **virtual offhand slot** using PacketEvents' silent send. Selene never clears, swaps, serializes or restores actual inventory items. Successful auth releases suppression and calls Paper's inventory synchronization. Optional blindness/darkness and player visibility are configured locally; pre-existing effects are restored after authentication and Bukkit's plugin-scoped visibility API is used. An optional auth location is applied, and the saved pre-auth location is restored after auth. Bukkit plugin-initiated teleports are trusted; do not run untrusted plugins on an auth server.

All player messages and native dialog labels live in config.yml. Paper 1.21.8 dialog capability and client protocol >=1.21.6 are checked before showing a **notice** with command instructions. Earlier versions use chat. Dialog passwords/input forms and image-rendering dialog captcha are **not implemented**. `stage` other than `AFTER_JOIN`, or `captcha-view` other than `MAP`, causes startup shutdown rather than fallback. No before-world/configuration stage or fork hook is implemented.

`resource-pack-provider` accepts NONE, Oraxen, ItemsAdder and verifies that the chosen external plugin is present. That plugin owns pack hosting, acceptance policy and distribution; Selene supplies no bundled pack and makes no provider API calls.

Current standalone policy uses explicit `captcha-required` (default true). Full admission modes, green snapshot synchronization, trust qualification and automatic hysteresis are not wired into this adapter yet. Use the Velocity integration for its implemented admission policy. Password-entry dialogs are not implemented.

Validation performed: Java compilation/shaded artifact, connection identity and stale/reconnect gate tests. Real client packet capture (including initial join, bundle packets, offhand map drawing, all 1.21.1–1.21.8 variants), actual Paper launch and full Rust/Velocity/Paper mTLS end-to-end are still required. This is a development build, not a production-security claim. Bukkit persists map IDs; renderer closures are removed on auth/disconnect but individual challenge map IDs can accumulate on disk and need operational monitoring.
