# Selene Paper adapter

Build `./gradlew :paper:build` and install the unclassified JAR from `paper/build/libs`. `packet-events-mode` accepts `AUTO`, `ENABLED`, or `DISABLED`. `AUTO` enables PacketEvents **2.9.5** only for `STANDALONE`; on a separate `PROXY_AUTH` server it stays unused. `ENABLED` forces packet protection for either role and requires PacketEvents to be installed. `DISABLED` uses only Paper event guards and an ordinary map item. Disabling it in `STANDALONE` permits the real inventory to reach the client before authentication and emits a warning. Selene compiles against Paper 1.21.8 with Java 21 bytecode. Runtime Java 21–26 is intended. Versions beginning 1.21.1 are intended compatibility targets, not an executed server/client matrix.

On first startup configure `plugins/Selene/config.yml`. `PROXY_AUTH` creates/reads **only relay.properties**, containing the Velocity relay endpoint, this Paper node's PKCS12 identity, and proxy trust store. It never creates or reads standalone backend settings. `STANDALONE` creates/reads **only standalone.properties**, with the backend endpoint. Role files reject unknown keys and malformed booleans. Passwords for PKCS12 files come from the named environment variables. Failure to initialize stops the server. PacketEvents remains a soft dependency in `plugin.yml` so Selene can report and enforce its role-specific requirement itself.

Standalone premium proof is exclusively `Bukkit.getOnlineMode()`. An offline-mode Paper cannot claim premium identity from UUIDs. Proxied deployments must use Velocity modern secure forwarding and prevent direct player access to the auth server; the relay owns authoritative player identity, IP, session, and premium status. Selene is an auth-server adapter, not a plugin to install on every destination server.

Locked players use `/selene:captcha <digits>`, `/selene:login <password>`, and `/selene:register <password> <password>`. Only these namespaced roots reach Bukkit before authentication, so another plugin cannot shadow a short alias such as `/login`. Backend replies control progression. In `PROXY_AUTH`, Paper event guards prevent movement, inventory interaction, item use/drop/pickup, damage, public chat and unrelated commands; the player is also hidden according to local visibility settings. The auth server has no gameplay inventory to protect. In `STANDALONE`, PacketEvents additionally suppresses inventory/equipment packets and rejects interaction packets before Bukkit handlers because the real gameplay inventory exists there. Reconnects use distinct object identity and cannot inherit permission. Async callbacks check the exact session object before applying results. Disable/reload kicks existing players; hot reload is unsupported.

Captcha PNGs arrive from Rust and render into a private map. `STANDALONE` sends it as a virtual offhand slot through PacketEvents without changing the real inventory. `PROXY_AUTH` places it in the auth server's ordinary offhand and removes it only when the same Selene map is still present; this inventory is isolated from gameplay servers. Successful auth releases suppression and synchronizes the inventory. Optional blindness/darkness and player visibility are configured locally; pre-existing effects are restored after authentication and Bukkit's plugin-scoped visibility API is used. An optional auth location is applied, and the saved pre-auth location is restored after auth. Bukkit plugin-initiated teleports are trusted; do not run untrusted plugins on an auth server.

All player messages and native dialog labels live in config.yml. Paper 1.21.8 dialog capability and client protocol >=1.21.6 are checked before showing a **notice** with command instructions. Earlier versions use chat. Dialog passwords/input forms and image-rendering dialog captcha are **not implemented**. `stage` other than `AFTER_JOIN`, or `captcha-view` other than `MAP`, causes startup shutdown rather than fallback. No before-world/configuration stage or fork hook is implemented.

`resource-pack-provider` accepts NONE, Oraxen, ItemsAdder and verifies that the chosen external plugin is present. That plugin owns pack hosting, acceptance policy and distribution; Selene supplies no bundled pack and makes no provider API calls.

Current standalone policy uses explicit `captcha-required` (default true). Full admission modes, green snapshot synchronization, trust qualification and automatic hysteresis are not wired into this adapter yet. Use the Velocity integration for its implemented admission policy. Password-entry dialogs are not implemented.

Validation performed: Java compilation/shaded artifact, connection identity and stale/reconnect gate tests. Real client packet capture (including initial join, bundle packets, offhand map drawing, all 1.21.1–1.21.8 variants), actual Paper launch and full Rust/Velocity/Paper mTLS end-to-end are still required. This is a development build, not a production-security claim. Bukkit persists map IDs; renderer closures are removed on auth/disconnect but individual challenge map IDs can accumulate on disk and need operational monitoring.
