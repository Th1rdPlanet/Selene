# Selene protocol v1

MoonLightBridge raw method ID 1397046273 (0x53454c01), UTF-8 JSON bodies <= 262144 bytes. This version uses explicit DTOs over the framework raw channel; no generated protobuf contracts. The shipped Rust service uses mTLS TCP in deployment. Development plaintext is explicit loopback-only.

Request fields always present: op, session, username, ip, password, answer (strings); premium, captchaRequired (booleans). Java record AuthRequest in ru.moonlightproject.dev.selene.core. Missing strings normalize to empty at boundary. Session is a server-generated UUID per connection, never supplied by player input. Username [A-Za-z0-9_]{3,16}, canonical lowercase for storage. ip parsed as an IP address, never hostname.
Reply fields: status, session, image (base64 PNG or empty), green (map canonical username -> trusted IP), premiumNames (array canonical usernames), retryAfter (integer seconds). Unknown map/list defaults empty. AuthReply record same package.
Operations: profile -> ACCOUNT_PREMIUM / ACCOUNT_OFFLINE / ACCOUNT_NEW; begin -> CAPTCHA (image) / LOGIN / REGISTER / AUTHENTICATED; answer -> same continuation or CAPTCHA_INVALID; register/login -> AUTHENTICATED / INVALID_CREDENTIALS / ACCOUNT_EXISTS / RATE_LIMITED; close -> CLOSED; trust -> TRUSTED (requires authenticated elapsed qualifying time); snapshot -> SNAPSHOT (green and premiumNames). Error statuses: INVALID_REQUEST, EXPIRED, UNAVAILABLE, BUSY. Begin premium is supplied ONLY from platform's verified online handshake. Password not required on premium session; existing offline account must not be converted by begin premium. Captcha cannot be bypassed by submitting login before answer. Repeated begin same session must not reset state/attempt budgets.

Paper->Velocity relay: same JSON DTOs, 4-byte big endian frame length + body over mTLS, one request/reply per connection, bounded frame/time/work. Velocity generates a random session ID for the exact physical player connection and sends it through that player's exact `ServerConnection` on the registered `selene:session` channel; client-originated messages on that channel are consumed by Velocity. Paper acknowledges the token, Velocity retries a bounded number of times, and failure closes the connection. Paper waits for this token before `begin`, and every relay operation must carry the exact ID. Paper can request begin/answer/register/login/close only for the current player assigned to that auth server; proxy ignores supplied username/IP/premium/captchaRequired and uses authoritative connection values. A delayed request from an older connection cannot bind to its replacement. No arbitrary snapshot/profile/trust forwarding from Paper. Replies carry no password. Server verifies proxy certificate/hostname and proxy verifies exact configured certificate fingerprint for its named auth server. TLS keys PKCS12, passwords supplied through named environment variables. Backend PEM keys/certs.
